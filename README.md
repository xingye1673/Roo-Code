# Roo Code (原名 Roo Cline)

**Roo Code** 是一个在您编辑器中运行的 AI 驱动的**自主编码助手**。它可以：

- 使用自然语言交流
- 直接在您的工作区读写文件
- 运行终端命令
- 自动化浏览器操作
- 集成任何 OpenAI 兼容或自定义 API/模型
- 通过**自定义模式**调整其"个性"和功能

无论您是在寻找灵活的编码伙伴、系统架构师，还是像 QA 工程师或产品经理这样的专业角色，Roo Code 都能帮助您更高效地构建软件。

查看 [CHANGELOG](CHANGELOG.md) 获取详细更新和修复信息。

## 3.0 版本新功能 - 聊天模式！

您现在可以选择不同的提示来更好地适应您的工作流程。以下是可用的模式：

- **Code:**（现有行为）默认模式，Cline 帮助您编写代码和执行任务。

- **Architect:** “您是 Cline，一位软件架构专家...” 适合思考高层次的技术设计和系统架构。不能编写代码或运行命令。

- **Ask:** “您是 Cline，一位知识渊博的技术助理...” 适合询问有关代码库的问题或深入研究概念。同样不能编写代码或运行命令。

**切换模式：**
非常简单！在聊天输入的左下角有一个下拉菜单可以切换模式。就在旁边，您会找到一种方法来切换与当前模式相关的 API 配置文件（在设置屏幕上配置）。

**为什么添加这个功能？**

- 它可以防止 Cline 在您只想思考或提问时过于急于解决问题。
- 每种模式会记住您上次使用的 API 配置。例如，您可以为 Architect 和 Ask 使用更深思熟虑的模型，如 OpenAI o1，而在编码任务中使用 Sonnet 或 DeepSeek。
- 它基于研究表明，将“思考”与“编码”分开可以获得更好的结果，这在 aider 的这篇非常有见地的[文章](https://aider.chat/2024/09/26/architect.html)中得到了很好的解释。

目前，切换模式是一个手动过程。未来，我们希望赋予 Cline 根据上下文建议模式切换的能力。现在，我们非常感谢您对这一功能的反馈。

## 重要功能

### 自适应自主性

Roo Code 使用**自然语言**沟通并提出行动建议——文件编辑、终端命令、浏览器测试等。您可以选择它的行为方式：

- **手动确认**：审查并批准每个步骤以保持完全控制。
- **自主/自动确认**：授予 Roo Code 无中断运行任务的能力，加快常规工作流程。
- **混合模式**：自动批准特定操作（如文件写入），但需要确认风险较高的任务（如部署代码）。

无论您的偏好如何，您始终对 Roo Code 的操作拥有最终决定权。

---

### 支持任何 API 或模型

使用 Roo Code：

- **OpenRouter**、Anthropic、Glama、OpenAI、Google Gemini、AWS Bedrock、Azure、GCP Vertex 或本地模型（LM Studio/Ollama）——任何**OpenAI 兼容**的模型。
- 每种模式使用不同的模型。例如，架构使用高级模型，而日常编码任务使用更便宜的模型。
- **使用跟踪**：Roo Code 监控每个会话的令牌和成本使用情况。

---

### 自定义模式

**自定义模式**让您可以塑造 Roo Code 的角色、指令和权限：

- **内置**：
    - **Code** – 默认的多用途编码助手
    - **Architect** – 高层次的系统和设计见解
    - **Ask** – 深入探索的研究和问答
- **用户创建**：输入 `Create a new mode for <X>`，Roo Code 会为该角色生成一个全新的角色——包括定制的提示和可选的工具限制。

每种模式都可以有独特的指令和技能集。在**提示**选项卡中管理它们。

**高级模式功能：**

- **文件限制**：模式可以限制为特定的文件类型（例如，Ask 和 Architect 模式可以编辑 markdown 文件）
- **自定义文件规则**：定义您自己的文件访问模式（例如，仅限 `.test.ts` 测试文件）
- **直接模式切换**：模式可以在需要时请求切换到其他模式（例如，切换到 Code 模式进行实现）
- **自我创建**：Roo Code 可以帮助创建新模式，包括角色定义和文件限制

---

### 文件和编辑器操作

Roo Code 可以：

- **创建和编辑**项目中的文件（显示差异）。
- **自动响应**lint 或编译时错误（缺少导入、语法错误等）。
- **通过编辑器的时间线跟踪更改**，以便您可以在需要时审查或还原。

---

### 命令行集成

轻松在终端中运行命令——Roo Code：

- 安装包、运行构建或执行测试。
- 监控输出并在检测到错误时进行调整。
- 让您在继续工作时保持开发服务器运行。

您可以批准或拒绝每个命令，或为常规操作设置自动批准。

---

### 浏览器自动化

Roo Code 还可以打开**浏览器**会话以：

- 启动本地或远程 Web 应用。
- 点击、输入、滚动和捕获屏幕截图。
- 收集控制台日志以调试运行时或 UI/UX 问题。

非常适合**端到端测试**或在不需要不断复制粘贴的情况下进行视觉验证。

---

### 使用 MCP 添加工具

使用**模型上下文协议 (MCP)** 扩展 Roo Code：

- “添加一个管理 AWS EC2 资源的工具。”
- “添加一个查询公司 Jira 的工具。”
- “添加一个提取最新 PagerDuty 事件的工具。”

Roo Code 可以自主构建和配置新工具（需要您的批准），以立即扩展其功能。

---

### 上下文提及

当您需要提供额外的上下文时：

- **@file** – 在对话中嵌入文件内容。
- **@folder** – 包含整个文件夹结构。
- **@problems** – 拉取工作区错误/警告以供 Roo Code 修复。
- **@url** – 从 URL 获取文档，将其转换为 markdown。
- **@git** – 提供 Git 提交或差异列表以供 Roo Code 分析代码历史。

帮助 Roo Code 专注于最相关的细节，而不会超出令牌预算。

## 安装

Roo Code 可在以下平台上使用：

- **[VSCode Marketplace](https://marketplace.visualstudio.com/items?itemName=RooVeterinaryInc.roo-cline)**
- **[Open-VSX](https://open-vsx.org/extension/RooVeterinaryInc/roo-cline)**

1. **在编辑器的扩展面板中搜索“Roo Code”** 以直接安装。
2. 或从 Marketplace / Open-VSX 获取 `.vsix` 文件并**拖放**到您的编辑器中。
3. **从活动栏或命令面板中打开** Roo Code 以开始聊天。

> **提示**：使用 `Cmd/Ctrl + Shift + P` → “Roo Code: Open in New Tab” 将 AI 助手停靠在文件资源管理器旁边。

## 本地设置和开发

1. **克隆** 仓库：
    ```bash
    git clone https://github.com/RooVetGit/Roo-Code.git
    ```
2. **安装依赖项**：
    ```bash
    npm run install:all
    ```
3. **构建** 扩展：
    ```bash
    npm run build
    ```
    - `bin/` 目录中会出现一个 `.vsix` 文件。
4. **手动安装** `.vsix`（如果需要）：
    ```bash
    code --install-extension bin/roo-code-4.0.0.vsix
    ```
5. **调试**：
    - 在 VSCode 中按 `F5`（或 **运行** → **开始调试**）以打开一个加载了 Roo Code 的新会话。

我们使用 [changesets](https://github.com/changesets/changesets) 进行版本控制和发布。查看我们的 `CHANGELOG.md` 以获取发布说明。
